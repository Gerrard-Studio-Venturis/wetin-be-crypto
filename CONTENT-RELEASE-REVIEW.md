## Concrete assessment mapping for implementation

Use one full KC activity per module, with A and B as alternative forms. A passing attempt on either accepted form records its exact activity/form/rubric version and that module's **four declared outcomes**. Do not require both forms in sequence. Reuse this full KC for experienced entry, showing the same outcomes and required criteria before starting. Prior experience, self-report and reading are not passes; successful entry does not complete unread lessons. No separate challenge bank is needed in the baseline.

Require every published E and C decision/rationale pair. Matching questions require all listed fields. Both action and reason must be correct; no aggregate percentage can compensate for any missing required pair. A failed full KC gives criterion feedback, but **no reusable partial outcome credit**. Optional free text can be reflective feedback only; it has no automatic scoring rule. Both bank label conventions must be preserved: modules 01–04 use action A/B/C and reason 1/2/3; modules 05–08 use A/B/C for both. Store choices by stable field/choice identity rather than confusing their displayed labels.

Guest expiry/clearing can remove guest evidence; it does not create a general time-based expiry for saved account mastery.

PM passes record the named fictional application and declared outcomes, **without gate-credit reuse in the initial implementation**. Capstone success does not replace all module checks. This deliberately leaves cross-activity equivalence out until it has an explicit reviewed mapping. A/B forms are intended content-equivalent alternatives, not measured psychometric equivalents. Two forms remain a small exposed bank: later retries may revisit a seen form. Show and store attempt/form history, allow rereading, and make no unseen-test or proctored-examination claim. Do not count option shuffling as a new equivalent form.

## Extraction, manifest and version contract

Treat the six full content-pack files at the named handoff commit as the writing manifest. Preserve canonical L/O/KC/PM/article/hub/glossary identities; import the expanded seed revision once, rather than duplicating the older sample. Store each learner-copy revision separately from source/reviewer metadata. For every activity publish an immutable revision identifier, e.g. `KC-04:A:r1`, with fixture, item/choice IDs, required classes, private key/rationale set, mapped outcome revisions, prerequisite mapping revision and approval/source state. The readable identifier is an example, not a forced database schema. Content documents currently say v0.1; that file version is not a substitute for distinct activity revisions. Preserve the reviewed commit reference and a content digest in the import/release manifest. Later copy, fixture or key changes produce a new revision; production never silently rewrites a bound attempt.

Normal replacement can grade an already-started attempt against its bound valid version, while reporting current applicability separately. A confirmed essential key/content error holds affected current evidence and in-flight attempts, preserves responses/history, and offers corrected content. Never grade fresh credit against a known wrong key or quietly substitute new questions. An outcome-neutral voice correction does not erase achievements. Material criterion/outcome changes need explicit equivalence or a refresh mapping with affected dependencies recorded.

Learner delivery excludes facilitator keys, unreleased explanations and private reviewer notes from HTML, REST, search, feeds and caches. Feedback after submission is scoped to that attempt/version. The public planning repository already contains keys; application access separation does not make the source bank secret or prove independent mastery.
